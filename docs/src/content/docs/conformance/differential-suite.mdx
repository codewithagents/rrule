The conformance suite is the primary trust artifact for rrule-ts. Every expansion result is
compared against ground-truth oracles, so behavior is provably correct and not just tested in
isolation.

## Three-way oracle design

The suite uses three oracles:

1. **python-dateutil 2.9.0.post0** (primary ground truth). python-dateutil is the reference
   implementation used by major calendar software including GNOME Calendar and KDE PIM. Its
   behavior on RFC 5545 cases is treated as authoritative.

2. **rrule.js** (known-divergence reference). rrule.js is the dominant JavaScript RRULE library.
   It is used as a reference to document where rrule-ts and rrule.js deliberately differ, and
   why.

3. **rrule-ts itself** (subject under test). Each expansion result from rrule-ts is compared
   against the dateutil output in the corpus.

## Corpus structure

The corpus is committed to `packages/conformance/corpus/corpus.json`. It is hermetic: CI does not
require Python to run the conformance tests. Python is only needed when regenerating the corpus
after adding new cases.

**Corpus coverage:**

| Category                                         | Cases    |
| ------------------------------------------------ | -------- |
| All 7 FREQ values (SECONDLY through YEARLY)      | Covered  |
| BYSETPOS-last (-1)                               | Covered  |
| Ordinal BYDAY (e.g. -1FR, 2MO)                   | Covered  |

| BYYEARDAY                                        | Covered  |

## CI hermeticity

Because the corpus is committed JSON, the CI test suite runs without any Python dependency. The
conformance tests read `corpus.json`, expand each case with rrule-ts, and assert that the output
matches the committed python-dateutil ground truth.

To regenerate the corpus after adding new cases, run the Python oracle script locally:

```bash
pnpm --filter rrule-ts-conformance fuzz
```

<Aside type="note" title="Corpus regeneration requires Python">
  Regenerating the corpus requires Python 3.x with python-dateutil installed. CI does not require
  Python because the corpus is pre-committed. Only the corpus maintainer (Benjamin) regenerates it.
</Aside>

## Known divergences from rrule.js

Where rrule-ts and rrule.js produce different results, the conformance suite documents the
divergence with a rationale. In all known cases, rrule-ts follows the python-dateutil behavior
(which is the RFC 5545 ground truth).

Key divergences:

- **BYWEEKNO year boundaries.** rrule.js and rrule-ts differ on whether days in late December
  that belong to ISO week 1 of the next year are included. rrule-ts follows dateutil. See the
  [BYWEEKNO guide](/guides/byweekno).

- **Negative BYMONTHDAY with MONTHLY FREQ.** Edge cases around negative day values at month
  boundaries produce different results. rrule-ts follows dateutil.

- **DST gap handling.** rrule.js uses `Date` and does not handle spring-forward gaps correctly.
  rrule-ts uses `Temporal.ZonedDateTime` with explicit disambiguation.
