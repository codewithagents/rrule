## Why rrule-ts?

<CardGrid>
  <Card title="Temporal-native" icon="approve-check-circle">
    Built on the TC39 Temporal proposal. Uses `globalThis.Temporal` on Node 26+ and modern
    browsers. Falls back to any Temporal polyfill via `setTemporal()`. No date math hacks.
  </Card>
  <Card title="Zero runtime dependencies" icon="approve-check">
    The library has no bundled dependencies. Temporal is accessed via `globalThis.Temporal` or an
    injected polyfill. Your bundle only pays for what you import.
  </Card>
  <Card title="TypeScript-first" icon="seti:typescript">
    Every function has precise return types. `parse()` returns `Result<RRuleOptions, string>`.
    `validate()` returns `Result<RRuleOptions, ValidationError[]>`. No silent failures.
  </Card>
  <Card title="Differential conformance suite" icon="star">
    Every expansion result is compared against python-dateutil 2.9.0 as the ground-truth oracle,
    and rrule.js as a known-divergence reference. Behavior is provably correct, not just tested in
    isolation.
  </Card>
</CardGrid>

## Install

```bash
npm install rrule-ts
```

On Node.js versions below 26, inject a Temporal polyfill before using date-expansion features:

```ts
import { setTemporal } from 'rrule-ts'
import { Temporal } from 'temporal-polyfill'

setTemporal(Temporal)
```

On Node.js 26 and above, `globalThis.Temporal` is used automatically.

## Quick example

```ts
import { parse, validate, stringify } from 'rrule-ts'

const result = parse('RRULE:FREQ=WEEKLY;BYDAY=MO,WE,FR;COUNT=10')
if (!result.ok) {
  console.error(result.error)
  process.exit(1)
}

const validation = validate(result.value)
if (!validation.ok) {
  for (const e of validation.error) {
    console.error(`${e.ruleId}: ${e.message}`)
  }
  process.exit(1)
}

console.log(stringify(validation.value))
// RRULE:FREQ=WEEKLY;COUNT=10;BYDAY=MO,WE,FR
```
